# Graphics architecture

Two subsystems, deliberately separate:

- **AirGraph** draws pixels: rectangles, rounded rectangles, text, surfaces,
  clipping, scaling. It has no concept of a window.
- **WinDown** arranges windows: positions, focus, z-order, hit testing. It has no
  concept of a pixel format.

Anything that needs both belongs in the layer above them, not inside either.

## AirGraph

`include/airgraph.h` and `kernel/airgraph.c` provide:

| Area | API |
| --- | --- |
| Device | `ag_device_init`, `ag_device_shutdown` |
| Surface | `ag_surface_init`, `ag_clear`, `ag_fill_rect` |
| Shapes | `ag_round_rect`, `ag_round_frame` |
| Text | Caller-supplied `sp_text_fn`; AirGraph does not own a font |
| Viewport | `ag_viewport_init_adaptive` with `AG_SCALE_STRETCH` |
| Pixels | `AG_PIXEL_XRGB8888` |

AirGraph is a CPU renderer. On QEMU it writes to a Bochs/QEMU linear
framebuffer; that is a display target, not GPU acceleration, and the code does
not pretend otherwise.

### Surface model

The desktop renders to an off-screen surface and blits it to the framebuffer, so
a frame is never half-drawn on screen. If the off-screen buffer cannot be
allocated, the code falls back to direct rendering and logs that it did so.

Colours are XRGB8888: the high byte is unused and every value is masked with
`0x00FFFFFF` before reaching a widget, so a theme cannot smuggle in an alpha
value that breaks blending.

## Framebuffer and display profiles

`include/vbe.h` and `kernel/vbe.c` set a linear framebuffer through the Bochs
DISPI interface. If the framebuffer cannot be opened, the desktop **refuses to
fall back to VGA text silently**: it logs a fatal error and the kernel panics,
because a half-initialised display is worse than a reported failure.

Display profiles select resolution and logical size:

| Profile | Resolution | Use |
| --- | --- | --- |
| Desktop | 800x600 | Default |
| Portrait | 600x750 | Phone |
| Wide | 1024x768 | Laptop |
| 4K | 3840x2160 | Large display |

The desktop scene is authored in an 80x25 logical cell grid and rasterised to
pixels, so layout code is resolution-independent and only the rasteriser cares
about pixel dimensions.

## WinDown

`include/windown.h` and `kernel/windown.c` implement the compositor: window
records, open/close, focus, z-order, title bars and body buffers. A window owns a
character-cell body buffer; the compositor composites windows and the pointer
onto the desktop surface.

## SprunkUI

`kernel/sprunkui.c` is the widget layer above AirGraph: panels, cards, buttons,
badges, separators, progress, toggles, checkboxes, text fields, list items,
sliders and status icons. `kernel/sprunkui_anim.c` adds pointer-aware animated
variants keyed by an `an_id`, backed by Airnimation (`kernel/airnim.c`).

Widgets are theme-driven through `struct sp_theme`: a colour set plus radius,
spacing and border width. `sp_theme_default` supplies a Material 3 dark palette.

### Accessibility

The theme loader (`kernel/desktop_theme.c`) measures WCAG relative-luminance
contrast between text and surface and reports whether a theme clears the AA floor
of 4.5:1. Luminance uses a 16-node sRGB linearisation table with interpolation
(`include/srgb_linear.h`, generated by `tools/gen_srgb_table.py`) because a
freestanding kernel has no `libm` and a full 256-entry table costs static memory
the image does not have. Worst-case error against the exact transfer function is
about 0.16% of full scale.

A theme below the floor is still installed, because it is the designer's choice,
but it is flagged in the serial log rather than passing silently.

## Status icons

`kernel/status.c` renders battery, network, GPU and VRAM indicators, and packs
the same information into the `SYS_UI_STATUS` syscall result so applications can
read it without parsing pixels.

## What is not here

No GPU acceleration, no shaders, no hardware cursor, no colour management beyond
XRGB8888, and no compositor effects beyond the rounded surfaces and animations
implemented in SprunkUI.
